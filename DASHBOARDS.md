# Grafana dashboards

## Included files

| File | Use |
| --- | --- |
| `vm-and-containers.json` | Classic external-sharing export; eight VM and container panels |
| `node-exporter.json` | Classic external-sharing export of the installed community Node Exporter dashboard |
| `vm-and-containers.v2.json` | V2 resource export preserving the current dashboard model |
| `node-exporter.v2.json` | V2 resource export preserving the current dashboard model |
| `prometheus-datasource.example.yml` | Data-source provisioning example based on the observed connection |

Exports were generated by Grafana 13.1.2. Grafana warns that converting V2 resources to classic JSON can omit V2-only features; both formats are included. Classic JSON parsed successfully, but importing into a separate Grafana instance has not yet been tested.

## Import into an existing monitoring environment

1. Ensure Prometheus can scrape the jobs in `prometheus.yml`. Its target names must resolve in your environment.
2. Configure a Grafana Prometheus data source. The lab uses `http://prometheus:9090`, reachable from Grafana's runtime network. Adapt this URL if your topology differs.
3. Open Grafana's dashboard import workflow and upload `vm-and-containers.json`.
4. When asked for the `prometheus` data source, select the configured connection. The classic exports use `${DS_PROMETHEUS}` to support this selection.
5. Import `node-exporter.json` in the same way.
6. Select the host and instance in the Node Exporter dashboard. Use a time range containing collected metrics.
7. Check that the healthy-targets panel reports the expected number of targets and that resource panels return data.

The published files use `origin_prometheus="lab"`. When importing into an existing lab with a different label value, update the dashboard selectors to match that value, or adapt a copy of the scrape configuration. Do not expect `lab` selectors to match differently labeled historical data.

These steps assume Grafana, Prometheus, Node Exporter, and cAdvisor are already deployed. They do not replace the missing original VM deployment files.

## VM and Containers panel guide

- **Scrape targets up:** sum of successful scrapes for the lab label; expected value was 3 during inspection.
- **VM uptime:** current node time minus boot time.
- **VM memory used:** percentage calculated from available and total memory.
- **Root disk used:** percentage calculated from available and total root-filesystem capacity.
- **VM CPU usage:** non-idle CPU time, averaged across CPUs.
- **Container CPU usage:** rate of container CPU time, grouped by container name and multiplied by 100. A value of 100 corresponds to one CPU core and can be exceeded.
- **Container memory working set:** working-set bytes grouped by container name.
- **VM network receive:** receive bytes per second for interfaces other than loopback; virtual interfaces may also be included.

## Portability changes

- Exported in external-sharing mode to remove selected host-variable values and instance metadata.
- Replaced the original `origin_prometheus` label value with `lab` in both dashboard formats.
- Normalized remaining classic Prometheus data-source references to `${DS_PROMETHEUS}`.
- Replaced legacy private IP addresses in inherited display overrides with documentation address `192.0.2.10`.
- Replaced inherited example cloud-host identifiers with `example-node`.
- Removed V2 creation timestamps and generation metadata, preserving dashboard resource names.

No live Grafana dashboard or Prometheus configuration was modified for publication.
